## Context

The native-frame lease retained a full-resolution RAM copy of **every** frame
the decode worker delivered to the runner — established and written down on
2026-08-07 when the operator asked and nobody knew the answer. On a 4K/25 fps
camera that is a ~24.9 MB pinned-RGB24 download 25 times a second, ~620 MB/s of
GPU→RAM traffic while the demand gate is open, and a steady-state ceiling of
`frameBytes × deliveredFps × ttlSeconds`. Raising the TTL to the 2 800 ms the
late-crop horizon actually needs multiplies that resident set directly.

The obvious decimation does not work. "Admit every Nth" is a count, and a crop
request is not a count — it names one specific `frameId`, so N−1 of every N
requests miss outright. Any every-Nth scheme has to ship with nearest-frame crop
resolution, which changes what a stored crop MEANS.

The set that does work was already known to the runner and never used: a
`frameId` leaves the runner only on a `FrameHandle` riding an inference result.
`PipelineAnalytics.processFrame` is the sole entry through which post-analysis
acquires a handle, and its only handle-bearing caller is
`handleInferenceResult`; the onboard-motion caller passes none. Everything
downstream — the detail plane's `nativeCropRef`, the event-media `keyFrame` /
`snapshot` / `thumbnail` captures, the face and plate recognisers, the
executor's `buildNativeFaceCropProvider` — descends from that one handle. No UI
caller holds one and no other addon imports the type.

That is a claim about the whole call graph, and this repo has twice shipped a
green suite that passed because a fake supplied what production forgot to
fetch. A code reading is not the same kind of evidence as a number.

## Decision

**The decode worker leases only frames the runner MARKED as having reached
inference** (`nativeLeaseAdmission: 'inferred'`), because that is exactly the set
a native-crop request can name. The mark is `markInferred(frameId)` on the
existing worker channel, sent from the same synchronous turn that received the
frame — the `pull` that follows is what decides the frame's retention, so IPC
ordering is the entire contract and there is no second mechanism. The
runner's `enqueueDetectionFrame` / `enqueueOccupancyFrame` report admission;
that boolean is the signal.

**The premise is carried as a counter, in both modes.**
`leaseUnmarkedCrops` counts every crop request naming a frame that was never
marked, and `leaseMarks` counts the marks received — because a worker receiving
no marks reports a perfectly clean premise, an empty window answering "I cannot
say" being indistinguishable from "nothing asked". The knob shipped as `all` and
the default was only changed after those two numbers said so on live traffic.

## Consequences

- **A caller that names a frame outside the inference set gets a miss, not a
  fallback.** It is visible (`leaseUnmarkedCrops` is a counter and a warn line
  carrying the frameId), and the recovery is a settings write, not a deploy —
  the knob is a cluster-wide orchestrator setting like the other three.
- **The newest delivered frame is unaffected.** It is the slot's `reserved`
  frame and `handleNativeCrop` resolves it through `FrameSlot.toBuffer`, never
  through the lease. That is the margin for the one-frame race between a mark and
  the supersede that consumes it, and it costs nothing because that frame is
  held either way.
- **The saving is the governor's admit ratio, not a fixed number.** A camera the
  two-plane governor is not throttling marks nearly everything and saves nearly
  nothing; the saving arrives exactly when the node is loaded, which is when it
  is wanted. Do not quote "80%" — read `leaseOffered` / `leaseAdmitted` off the
  metrics line for the camera in question.
- **`enqueueDetectionFrame` returning `boolean` is load-bearing.** A version that
  always returned `true` would leave every counter claiming a filter that never
  filtered. It is pinned by a test for that reason.
- The mark is a fourth knob on the existing settings → fork-env → `setting > env
  > default` plumbing, and it is a WORD where the other three are integers — a
  shared numeric parser would have turned it into `NaN`, failed its bounds, and
  silently reverted to the default with no error anywhere.

## Enforcement

Tests, each confirmed red with the filter removed:

- `packages/addon-pipeline/src/session-decode/__tests__/lease-admission-ledger.spec.ts`
  — marked kept, unmarked dropped, the marked window bounded, and a crop older
  than the window NOT counted as unmarked. Also the pair that separates "0
  unmarked crops" from "0 marks".
- `__tests__/lease-admission-retention.spec.ts` — `FrameSlot` + ledger +
  `NativeLeaseStore` composed as the worker composes them: a crop for a marked
  frame still hits after its unmarked siblings were dropped. The fakes carry a
  label so a wrong-frame retention reads as a wrong value, not a right count.
- `__tests__/mark-inferred-roundtrip.spec.ts` — the mark names the frame id, not
  a position, and precedes the pull that supersedes that frame.
- `pipeline-runner/__tests__/runner-governor.spec.ts` — admission is reported
  honestly for the governed, non-active and unknown-camera cases.

No guard script. "Nothing names a frame outside the inference set" is a property
of the call graph that a grep cannot check, and a grep-guard pretending
otherwise would read as verification. The counter is the enforcement, and it runs
in production rather than in CI.
