## Context

`@camstack/server` 1.2.218 reintroduced the GPU inference timeouts that
1.2.216 had fixed: ~3 760 `inference request timed out` an hour for 4 h 19 min
(16 215 lines), on a cluster whose previous hour had seen about five. Every
signal the release process trusts stayed green — typecheck, the suites, the
guards, `/health` 200, `runningVersion` read back per node. 1.2.219 fixed it
again as a side effect of the next deploy, and the regression was found a day
later by an audit that counted log lines per version by hand (2026-09-05).

A CI guard cannot see this: the rate exists only on the node, under load,
after the update. A Grafana alert would see it, but only where Loki is wired
and only if someone writes the query per deployment. The place that knows
both the previous rate and the new version is the runner itself.

## Decision

The detection provider runs an inference-timeout guard. Every five minutes it
records the timed-out inference requests on this node under the current
fingerprint (the closure version, `server@<runningVersion>`), persists the
last hour of buckets in the addon store, and — once the new fingerprint has a
quarter hour of its own — compares hourly rates with the fingerprint the
store handed over. Five times worse and above twenty an hour is a
`system.liveness-failed` finding keyed on the node (a persistent alert, an
ERROR line naming both versions and both rates); back under the ratio
dismisses it; five times better is one INFO line. A restart under the same
fingerprint compares nothing.

## Consequences

- Timeouts are counted per pool worker and summed; a worker restart resets
  its share and the guard reads a drop as "the new count is the delta".
- The rate is per hour, the unit the audit measured. Traffic doubling doubles
  it, which is why the ratio is five.
- The fingerprint is read from disk — the closure the runner script was
  started from (`<closure>/node_modules/@camstack/server/package.json`) —
  not asked of `server-management`: that cap is server-provided and the
  parent refuses to route it for a forked addon ("no provider registered",
  all three nodes, first deploy of the guard). A node whose runner is not
  inside a closure never compares.

## Enforcement

`inference-timeout-guard.spec.ts`: the verdicts, the ONE finding per
regression, the recovery, the same-fingerprint restart. Removing the emit
turns two of them red (checked 2026-09-05).
