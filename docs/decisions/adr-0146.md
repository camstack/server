## Context

The scene monitor emits a **latch**: "this region has stopped matching the
picture you captured, at least once, since you last reset it". The operator's
own example is a wheelie bin left at the kerb — they want to be told once, and
to still see it at breakfast.

A latch is not a notification. A notification is a moment; a latch is a *claim
that persists*, and clearing it costs the operator a deliberate act. That
asymmetry is the whole subject of this record.

The obvious thing to do was to copy `NcConfirmGate`, which already ships every
hard part of putting a question to a vision model: the hardened system prompt,
the `jsonSchema` request, the lenient parse, the 448 px downscale, the 8 s
timeout, the per-device concurrency bound. We did copy all of it.

But `NcConfirmGate` **fails open**: when the model times out, is unreachable, or
answers something unparseable, the notification is delivered unjudged. That is
correct there and it is documented as such — suppressing a real alert is the
worse error, and the cost of a false one is a line nobody reads.

Copying that direction here produces a specific failure, and it is not
hypothetical: the vision model in this install is a local LM Studio process that
is routinely cold (measured p50 4.9 s warm, **15.3 s cold**, against an 8 s
timeout). An LM Studio restart during a windy afternoon would time out every
adjudication, fail open on each, and latch every scene on the property. The
operator would then walk round the house pressing Reset on alarms that never
happened — and, having done that twice, would stop believing the feature. A
latch that cries wolf is worse than no latch, because the whole value of the
latch is that it survives until someone acts on it.

The same asymmetry recurs three more times in this subsystem, and the first
implementation got all three wrong in the same direction:

- a check with **no comparable reference** (uncovered lighting, changed encoder
  model) returned bare, which downstream was indistinguishable from "matched";
- a check taken **while the camera was busy** counted toward the flip, so a van
  parked in front of the bin could latch it;
- a **moved camera** diverged forever with a perfectly plausible cosine.

## Decision

**When the authority that would confirm a latched state change cannot answer,
the change does not commit.** This applies to every adjudicator in the path, not
only the vision model: an absent reference, a non-quiet frame, a shifted view
and an unreachable model all HOLD the pending flip rather than committing it,
and each reports a named `unavailable` cause rather than a silence.

The inverse knob exists (`SceneConfirmSchema.onTimeout: 'flip'`) and the UI
states which direction is in force, because an operator who would rather have a
false latch than a missed one is entitled to that — but it is never the default,
and it is never implicit.

## Consequences

- A vision model that is down for a week means a scene that reports nothing new
  for a week. This is the accepted cost, and it is why the gate WARNs on every
  fail-closed decision with a running counter: the failure must be discoverable
  from the logs alone, because it is by construction invisible in the UI.
- `verdict: 'unknown'` has to be a real value carried end to end, not a null and
  not a stale `matched`. Every consumer — the badge, the coverage line, the rule
  status — must render "can't tell" as its own state. A UI that collapses
  `unknown` into `normal` re-creates the exact silence this record exists to
  prevent.
- A held flip also DROPS the pending hysteresis run, so a scene must earn its N
  observations again. Without that, the moment the model returned, one check
  would commit a flip built from observations made while nothing could judge
  them.
- This is the OPPOSITE of [D-NcConfirmGate](../architecture/notifications.md)'s
  direction, and the two now coexist in one repo. That is deliberate and it is
  the reason `SceneConfirmGate` is a separate class rather than a flag on the
  existing one: a shared gate with a direction parameter would be one edit away
  from silently flipping the wrong consumer.

## Enforcement

`packages/addon-post-analysis/src/pipeline-analytics/scene/__tests__/scene-confirm-gate.spec.ts`
pins all four no-answer paths (timeout, unavailable model, unparseable reply, no
crop) plus the busy-queue overflow. Forcing `onNoAnswer`'s direction to
`confirmed` turns five tests red — verified by doing it.

The three non-LLM adjudicators are pinned in `scene-engine.spec.ts`
(quiet gate, observation spacing, view-shift anchor) and `scene-scoring.spec.ts`
(no cross-condition fallback; `bestScore: null` distinguishes "nothing
comparable" from "compared and missed"). Each was neutralized to a constant and
each turns exactly its own test red.

Nothing guards the *principle* across future adjudicators — a fifth one added to
this path could fail open and no script would notice. Review only, which is why
this record states the rule rather than only the four cases.
