## Context

The HA export's per-node rows (D2/D3 of the synthetic devices) fanned
`recording.getStorageUsage` out to every node in the topology, pinned with
`nodePin(node.id)`. `recording` is a **singleton** cap: the recorder runs on one
node and boots inert everywhere else — the agents log `recorder INERT on this
node — recording assigned elsewhere` at every start. A pinned read at an inert
node is a question that node cannot answer by construction, and the hub logged
it as a failure: `could not read storage usage for a node, its disk entities go
unknown`, 685 times a day on 2026-09-05, one per node per reconcile, never once
producing a value. The same loop asked an OFFLINE node for its package status
(a ghost `hub-test` row that no longer existed as a process) — 130 more lines a
day.

The first reading of those lines was "the agents' recorders are not registering"
— a routing fault. It was not: the recorder was doing exactly what its placement
says, and the fault was in the caller assuming every node owns every cap.

## Decision

A cap whose provider mode is `singleton` is read **once**, **unpinned**, and its
answer is attributed to the node the answer names (`nodeId` in the response).
Every other node is **unread**, never failed: its rows stay `unknown` without a
warning, because unknown is the truth about a node that does not own the cap. A
per-node read is issued only for a cap the node can own, and never to a node the
topology already calls offline.

## Consequences

- `footageForNode(nodeId, usage)` is the only place a storage answer becomes a
  node row; `shouldReadPackageStatus(node)` is the only gate for the per-agent
  read. Both are pure and tested.
- Footage rows for nodes other than the recorder's are structurally `unknown`.
  If recording ever becomes multi-node, the cap stops being singleton and this
  record is superseded — the fan-out does not come back on its own.
- A warning about a read now means the read the cluster CAN answer failed.

## Enforcement

Unit tests on `node-reads.ts`. Review only for the general rule; no guard
inspects cap mode at call sites.
