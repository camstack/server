## Context

[D81](adr-0081.md) gave a track a retrain lifecycle — `none → staging →
trained` — and shipped it with the third state deliberately unreachable. Nothing
wrote `'trained'`, and `setTrackFlags` refused a `markForTrain` write against a
trained track in either direction. That was correct and it was also a promise:
until a curation surface existed, a marked track was pinned against retention
for ever with no way to finish with it.

D81 also made `trained` EVICTABLE again, and the whole safety of that rests on
one sentence in the record: *"the retrain page COPIES each frame it selects into
the retrain dataset at selection time"*. If the dataset held references instead,
a track returning to evictable would take the dataset's own entries with it —
retroactively, silently, and only visibly at the next fine-tune.

Two more failures were already on file and had to not be repeated. **D52**: one
vector index, one crop derivation — the CLIP rebuild derived its own rectangle
and created the feature-space split it was written to remove. And the fleet's
own taxonomy: a UI that lets a macro class be typed into a label field produces
a table where "every person box" is no longer answerable without knowing every
string anyone ever typed, and no amount of reading it afterwards un-mixes it.

## Decision

**The retrain dataset owns COPIES, taken at selection time, and stores exactly
ONE rectangle per subject.**

Three rules follow, and each one is a precondition of the next:

1. **Copy on select, copy first.** Selecting a frame writes its bytes into
   `retrain/<deviceId>/<trackId>/…` and a row in
   `pipeline-analytics:retrain-frames` before anything else happens.
   `copyFrame` answers from the COPY INDEX first and only reads the source when
   there is no copy — so an original that evaporated blocks the selection of
   that original and never the copy already taken. Inverting those two reads
   makes an annotation made last week unopenable the day retention swept its
   track, and the failure looks like data loss with no cause.

2. **Completing a track is the only writer of `'trained'`, and it REFUSES a
   track the dataset holds no copies from.** `trained` un-pins the media;
   completing without a copy is a delete order for material nothing extracted
   anything from. `restage` (`trained → staging`) is the deliberate return the
   generic toggle refuses to make, and it leaves the copies and annotations
   alone — "put this back" must not be a destructive act wearing a navigational
   name.

3. **One canonical box, geometry derived at export.** `retrain_annotations.bbox`
   is normalised `[0,1]` against the FULL frame, always. The letterboxed root
   shape, the zone-cropped package shape and the subject-cropped classifier
   shape are computed in `retrain-geometry.ts` at export and never stored. A box
   that does not exist in a target space comes back ABSENT, never clamped — a
   clamped box is a wrong label, it teaches the model that the subject ends
   where the crop ends.

**The three annotation tiers are separate columns and a macro class is never a
label.** `macroClass` is a closed set (the exported detector's classes);
`label` and `subLabel` are open strings (the vocabulary the page exists to
teach). The guard is at the WRITE, case-insensitively, on both open tiers,
because a mixed taxonomy is not repairable by reading it.

**A false positive is taught by OMISSION, and the omission is recorded.** The
frame enters the dataset fully annotated and deliberately WITHOUT the box the
model drew; a `kind: 'model_error'` row with `assistModelId` + `assistScore`
records that the omission was deliberate and turns the frame into a
post-fine-tune regression test.

**The initial detection is a PROPOSAL.** It runs through
`pipelineRunner.runStatelessStep` on the COPY, so every proposed box arrives in
the coordinate space of the image it will be drawn on. For packages the request
is `rfdetr-package` on the ZONE CROP at 0.35; **a package proposal with no zone
is refused, never widened to the frame** — at that threshold a package detector
on a full frame proposes furniture, and the silent widening would read as a bad
model for as long as nobody checked which rectangle it ran on.

## Consequences

- The dataset costs disk twice for a selected frame, until the track is trained
  and its own media ages out. That is the price of the D81 eviction, and it is
  bounded by how many frames an operator selects rather than by retention.
- Two new declared collections (`retrain-frames`, `retrain-annotations`) and one
  blob prefix that **no age sweep and no owner cascade walks**. Deleting a
  retrain frame is only ever an explicit operator act (`deselectRetrainFrame`).
- The zone used for a `zoneCrop` derivation is recorded per frame in the export
  manifest (`zoneUsed`). A derived box whose reference rectangle is implicit is
  a box nobody can check.
- Eleven new cap methods on `pipeline-analytics`, all `auth: 'admin'` — marking
  a track stays viewer-level (D81), but building the training set the fleet's
  models are fine-tuned on is not.
- The bytes of the annotated archive leave through a data plane
  (`retrain-export`), not the cap, for the reason `getTrainingExportUrl` already
  does.

## Enforcement

- `retrain-copy-on-select.spec.ts` pins the copy-first ordering, and was
  red-verified: inverting the two reads in `copyFrame` fails the
  "evaporated original never invalidates the copy" case and nothing else.
- `retrain-lifecycle.spec.ts` pins the `no-frames-copied` refusal and both
  terminal-state guards.
- `retrain-geometry.spec.ts` pins that a subject outside the zone derives to
  `null` rather than a clamped rectangle.
- `retrain-assist.spec.ts` pins the package no-zone refusal, the 0.35 filter,
  and the tier guard in both casings.
- `retrain-boxes.spec.ts` (admin-ui) pins the letterbox coordinate conversion —
  the single most likely way this page would produce subtly wrong boxes.
- The taxonomy is pinned to the cap enum by a bidirectional type assignment
  (`MacroClassesAgree`), so adding a class on one side alone fails the build.
