## Context

`llm-runtime` today is **one llama-server child per NODE**, not per model. The
constraint is written into `LlamaSupervisor` — a single `private child:
ChildProcess | undefined`, no keyed collection — and into `start()`, which is a
stop-and-replace:

```ts
if (this.state === 'ready' && this.sameConfig(cfg)) return this.status()
if (this.child !== undefined) await this.stop()
```

So two `managed-local` profiles on one node do not coexist. They **evict each
other on every call**, and because a cold GGUF load is minutes on CPU, alternating
between a text profile and a vision profile makes both permanently slow while
looking, from the outside, like a slow model rather than thrashing. Nothing logs
the eviction.

The v1 header says this was deliberate ("models are RAM-heavy", operator
decision #3, no RSS watchdog). The operator has now asked for the opposite shape,
and the reason the original constraint existed — uncontrolled RAM — is
addressable directly rather than by allowing only one model.

Three things make this cheaper than it looks, and one makes it harder:

- `CrashPolicy` is **already keyed by id** (`Map<string, number[]>`); the
  supervisor only ever passes the constant `'llama'`. The per-model key is free.
- `LlmRuntimeStatus` **already carries `modelId`**, and `memoryBytes` /
  `vramBytes` / `freeBytes` are already declared and never populated. The budget
  is a fill-in-the-blanks job on existing contracts, not a schema migration.
- `LlamaSupervisor` is otherwise a clean single-process lifecycle (spawn, health
  gate, crash breaker, idle stop). It should be KEPT as-is and instantiated N
  times, not rewritten.
- Four cap methods take `z.object({})` — `stop`, `status`, `listLocalModels`,
  `getDiskUsage` — and mean "the one process on this node". Those signatures are
  what makes this a **train-bound** change: hub and agent must agree.

## Decision

A node runs **one `LlamaManager`**, which owns a `Map<modelKey, LlamaSupervisor>`
— one child process per ACTIVE model — and admits a new model only if its
estimated resident size fits a configured **RAM budget** for that node, evicting
least-recently-used ready models to make room. A model that still does not fit is
**REFUSED with a message naming the budget and the shortfall**; it is never
started anyway, and never silently substituted for a model that does fit.

Idle eviction stays where it already works (`idleStopMinutes`, per model), and
freeing a model returns its bytes to the budget.

Size estimate, in order: `ManagedModelCatalogEntry.minRamBytes` for a catalog
ref; otherwise `stat()` on the GGUF. `url` and `path` refs synthesise catalog
entries with `sizeMB: 0`, so the stat fallback is REQUIRED, not a nicety — a
budget that reads 0 for every custom model is not a budget.

Cap surface, changed together:

- `status` returns the node's models, not one model:
  `{ nodeId, models: LlmRuntimeStatus[], ramBudgetBytes, ramCommittedBytes }`.
- `stop` takes `{ modelId?: string }` — omitted means all, which is what
  `onShutdown` needs.
- `listLocalModels` / `getDiskUsage` are unchanged (they are about DISK, which
  was always per-node).
- `llm.getRuntimeStatus/startRuntime/stopRuntime` keep taking a `profileId` and
  select the one model that profile references.

## Consequences

- `AiAddon.onShutdown` currently awaits a single `stop()`. It becomes a stop-ALL
  with a bounded deadline, or shutdown hangs for N × `killGraceMs`.
- `defaultPickPort` binds `:0`, reads the port, closes, then spawns. With one
  process that is one narrow race; with N concurrent starts it is N races against
  each other. The manager must hold an allocated-port set and retry.
- `deleteModel` guards against deleting the loaded model by comparing one
  `basename`. It becomes a set-membership test over every running model.
- `downloadProgress` is a single module-closure `let`, so two concurrent installs
  already clobber each other's progress. Per-model processes make concurrent
  installs normal rather than rare, so it must become a map.
- The admin Runtimes tab renders one status per node and must render a list.
- Train-bound: an agent on an older build answers the old `status` shape. The
  hub must tolerate that for one release, or the release must move both.

## Enforcement

Tests, plus one guard. `buildLlamaArgs` is already covered by a test asserting
that every configured flag reaches argv and that an unset flag emits nothing —
that pattern extends to the budget: a test that admits models until the budget is
exhausted and asserts the REFUSAL names the shortfall, and one that asserts an
LRU eviction happened rather than an over-commit. There is no static guard that
can catch "started a model over budget", so the admission decision must stay in
ONE function that the tests call directly.

**Not yet implemented.** The flags half of this record shipped
(`batchSize`, `ubatchSize`, `flashAttention`, `mlock`, `noMmap`, `cacheTypeK/V`
are configurable and reach the command line); the manager, the budget and the cap
signature change did not.
