## Context

[D45](adr-0045.md) said one copy of every host-provided package per node.
[D24](adr-0024.md) and
[update-and-release.md](../architecture/update-and-release.md#the-canonical-topology--one-addon-root-per-node)
said one addon root per node. Both held on paper. In one evening (2026-08-07 →
08) three separate outages came out of copies that neither rule reached, and the
common shape is not "a second root" — it is **a second copy inside the one
root, and a bootstrap allowed to overwrite the runtime**.

**1. A rename is an install.** `@camstack/system` on `agent-a` was renamed
to `system.bak-pre-unshadow` as a "shadow cleanup". On an agent that directory
is the only builtins copy, and the node came up with zero infrastructure —
[D87](adr-0087.md). The mirror image was live on the Mac agent the next
morning: `system.bak-pre-1272-1786129145` still held a complete
`@camstack/system@1.2.3` from 2026-07-22, 97 MB, and the node had **no**
`addons/@camstack/system` directory at all — yet `addons/manifest.json` reported
`@camstack/system 1.2.3` with that boot's timestamp, and `lsof` showed the live
server process holding `better_sqlite3.node` mapped `txt` **out of the backup**,
against a 1.2.61 closure.

That is not one bug. Three independent consumers key on the `package.json`
inside a directory and ignore the directory's name:

| Consumer | What the rename did |
| --- | --- |
| `AddonLoader.loadFromDirectory` | loads it — its skip list is keyed on the PACKAGE name, so `@camstack/system.bak-…` was never skipped |
| `resolveAddonPackageDirs` (agent boot) | scans it |
| `AddonManifest.reconcileFromDisk` | `onDisk.set(pkgJson.name, …)` — the backup's version becomes the version every surface REPORTS |

So "I renamed it out of the way" is false in all three, and the version an
operator reads can be a directory nothing is supposed to run.

**What was tried first and was wrong.** The instinct both nights was to
*delete* the offending copy. That is what gutted `agent-a`: the judgement
"this is a shadow" was right on the hub and catastrophically wrong on an agent,
and the deletion left no evidence of what had been removed. A cleanup that
cannot be wrong is not available here; a cleanup that cannot be *undone* is the
thing to refuse.

**2. The image seed outranks the runtime.** The container entrypoint seeded
bootstrap addons with one unconditional
`cp -a /opt/camstack-seed-addons/@camstack/. "$ADDONS_DIR/@camstack/"`, fired on
any image seed-version change. The baked set is an artefact of build time and
goes stale immediately: the live `intel-1.2.32` image carries `addon-pipeline`
1.2.38 against 1.2.46 deployed, `addon-admin-ui` 1.2.21 against 1.2.34,
`addon-pipeline-orchestrator` 1.2.18 against 1.2.28. The next container recreate
onto the contract image — which the admin UI is *correctly* asking for, since
the seed is 1.2.32 and the contract is 1.2.75 — would have silently rolled every
one of them back. Nothing would have failed; the node would simply have been
running older code than the hub believed.

`AddonInstaller.ensureRequiredPackages` was already seed-only and stays so. The
destructive path was the shell, where no test in this repository could see it.

## Decision

**A package lives once per node, in the directory that bears its name.**

1. **The directory IS the identity.** A directory under the addon root whose
   basename is not the package it declares is residue, not an install.
   `reconcileFromDisk` refuses to adopt one, so no version surface can answer
   out of a backup.
2. **Residue is quarantined, never deleted.** `quarantineAddonResidue` runs at
   the top of the launcher — before the bootstrap seed writes into the root and
   long before any loader scans it — and RENAMES residue into
   `<addonRoot>/.quarantine/`, logging every move with its reason, both paths
   and the package it declared. Nothing is removed; a failed move is reported
   and the directory is left in place. Two triggers: a backup marker in the name
   (`.bak` / `.old` / `.orig`), or a declared name that is not the directory.
   Dot-prefixed installer stores (`.staging`, `.backups`, `.evicting`,
   `.npm-bootstrap`, `.quarantine`) and `node_modules` are never candidates.
3. **The image seed is first-boot bootstrap only.** The entrypoint seeds
   per package and only when that package is absent. It may never replace an
   installed one, whatever the version comparison would say — `<dataDir>/addons`
   is the runtime authority and a build-time artefact does not outrank it. New
   versions arrive by `camstack deploy` or the hub back-fill.
4. **`@camstack/system` is never seeded from an image or app bundle.** Its two
   legal sources are the running closure (`seedBuiltinsFromClosure`, which
   copies the version the node is ACTUALLY running) and
   `camstack deploy packages/system`. `shouldSkipClosureProvidedSeed` already
   encodes this; point 3 removes the shell path that could have re-planted a
   1.2.3 bundle copy on a 1.2.61 node.

## Consequences

- **A container recreate no longer converges addon versions.** It never
  legitimately did — it silently downgraded — but an operator who relied on that
  side effect now needs a `camstack deploy` or `clusterNodes.repairNodeAddons`.
  This is the correct trade: the back-fill is observable and bounded, the seed
  was neither.
- **`.quarantine` grows and nothing reclaims it.** Deliberate. `sweepBackups`
  bounds `.backups` because that store has an owner (the manifest's rollback
  pointer); quarantine has none, and a sweep that deletes what a human has not
  looked at reintroduces the failure this record exists for. Reclaiming it is an
  operator gesture.
- **Seed staleness becomes visible instead of self-correcting.** The image
  contract verdict (`packages/node-root/src/image-contract.ts`) is now the only
  thing that tells an operator the image is behind — which is what it was
  written for.
- **Per-addon provenance is still not exposed.** `AddonManifestEntry.source`
  carries `'npm' | 'local' | 'upload' | 'bundled' | 'seed'`, but
  `reconcileFromDisk` stamps `'seed'` on everything it discovers, including
  packages that arrived by `camstack deploy` and lost their entry. Until that is
  fixed the field is not trustworthy enough to render. See "Open" below.

## Open

The admin UI should show, per addon, ONE provenance — `deployed` /
`seeded` / `builtin-closure` — beside the version. The data almost exists: the
manifest has `source`, and the builtins are distinguishable because they come
from `<serverRoot>/current/node_modules/@camstack/system` rather than the addon
root. Two things must land first, or the surface would render a confident wrong
answer:

1. `reconcileFromDisk` must stop labelling every discovery `'seed'`. It should
   adopt an unknown directory with an explicit `'unknown'` provenance rather
   than asserting a source it cannot know.
2. `seedBuiltinsFromClosure` must record what it did — a `'closure'` source —
   instead of leaving reconcile to guess.
