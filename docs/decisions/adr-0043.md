## Context

An operator opened the device-export setup page on a phone and could read
everything on it except the one thing they came for. The label/value row put a
`w-32 shrink-0` label beside a `flex-1 truncate` value at every width, so
"Ingress token (…)" wrapped to two lines on the left and its value was cut
mid-word on the right, with the copy button squeezed between them. The table
below it was worse: its first column was `sticky left-0 w-64`, and the phone
viewport was narrower than that column alone, so the pin held its width
permanently and pushed every other column off the screen.

Neither is a styling bug. Both components look fine at desktop width and both
were written by someone who had checked them. What was missing in each case is a
*condition*: the two-column row and the pinned column are desktop concessions
that were applied unconditionally.

The first instinct — fix the export page — was wrong twice over. The rows and
the table are shared primitives (`device-export-panel.tsx`, `device-list/`), so
a page fix leaves every other consumer broken; and a survey found nine more
hand-rolled copies of the same row in `addon-admin-ui`, which is what a per-page
fix produces over time.

The second instinct, "make the font smaller", is the one the roadmap explicitly
forbids: it does not make a five-column table readable, it makes it unreadable at
a smaller size.

## Decision

A layout concession that only holds at desktop width is declared in
`lib/responsive.ts` as a token carrying its own breakpoint, and consumed by a
primitive. Concretely:

- A label/value settings row is `<SettingRow>`. It stacks below `sm` — label on
  its own line, value below it at full width, wrapping rather than truncating.
  No page hand-rolls one.
- A sticky first table column is pinned behind a breakpoint at or above which
  the *remaining* columns still fit beside it. For the device table that is `md`
  — the width at which the first optional column returns. A pin with nothing to
  scroll under it is not a feature.
- A wide table on a narrow viewport scrolls horizontally inside its own
  container with the page body never moving sideways. (The card mode and the
  `resolveTableLayout` choice this record first described were removed — see
  D862.) Shrinking the font is not an option.

Stated as a rule: **`sticky`, a fixed label width and `truncate` never appear
unconditionally in a shared primitive.**

## Consequences

- Every settings surface gets the stacking for free, and the nine hand-rolled
  rows in `addon-admin-ui` become migrations rather than redesigns.
- `lib/responsive.ts` grows: a token there is cheap, a breakpoint inlined in a
  component is the thing this record exists to stop.

## Enforcement

Tests, via `lib/tailwind-variants.ts`: `hasUnconditionalClass(className, util)`
is false when the utility only appears behind a variant, so a test can assert
the *decision* ("the name column is not pinned at every width") rather than a
class literal — which would guard churn instead, and would go stale on the first
padding change (see `docs/ui/conventions.md`, "Frozen-string tests have an
expiry date").

Guarded today: `composites/__tests__/setting-row.test.tsx` and
`composites/device-list/__tests__/sticky-name.test.tsx`. Both were verified by
restoring the pre-fix class strings and confirming they fail.

No repo-wide script yet — legitimate unconditional `sticky left-0` exists in the
pipeline matrices, where the pinned lane is the axis of the grid, so a blanket
grep would need an allowlist that weakens it to nothing. Review plus the two
tests is the current bar.
