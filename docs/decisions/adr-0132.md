## Context

The 2026-08-13 census (`docs/design/2026-08-13-durable-value-tracking-and-runtime-state.md`)
walked 24 stores that answer "remember a value across a restart" and found
three things.

**One.** Five of them — liveness, occupancy, stationary objects, snoozes, the
outbox — had each written the same 120 lines: declare a collection, mirror it
into RAM, reseed at boot, write behind the decision, choose a failure
direction. Five copies is five chances to choose the direction wrong, and two
of them had already been chosen wrong in the same week (the occupancy cold
baseline, the liveness flood). A sixth copy was being written while the census
was read.

**Two.** Nothing anywhere answered *"what survives a restart, and who owns
it"*. That question had to be answered by reading files. Two of the 24 held
state whose class nobody had ever decided, and both were live cold-start bugs:
`NodeStressController`'s move history (every restart granted a fresh
4-moves/hour failover budget and cleared every cooldown and return ban) and
`DeviceFeaturesMirror` (a mirror that was never seeded, so the first read after
a boot resolved `[]` and dialled a sleeping battery camera awake — the file
documented that hole rather than fixing it).

**Three.** CamStack already has Home Assistant's *short-term* tier and never
called it that — `pipeline-analytics:{motion,audio,object}-events`, ~98,000
rows/day behind a 7-day window. What it does not have is the *long-term* tier.
The sharpest consequence: node stress `observe` is the DEFAULT mode, its
documented purpose is "this is how the thresholds get measured on your fleet",
and it wrote to nothing but the log.

## Decision

**One primitive, one catalogue, one guard; the meaning of a value stays with
its owner.** Same split D3 applies to capability registration and D62 to
per-camera switches.

1. **`DurableLedger`** (extracted verbatim from `liveness-ledger.ts`, D130) owns
   the mechanics and nothing else. Its contract: the RAM mirror is the read
   surface and the store is never on a decision path; **a failed load never
   clears the mirror** (no knob — dropping remembered state on a transient
   error is what produced the flood); **an empty mirror SEEDS**, so the failure
   direction is always toward discard; a malformed row is skipped, not
   repaired; the write mode (`write-behind` / `write-through`) is declared per
   collection, never chosen per call site. Consumers: liveness (the donor),
   occupancy, stationary objects, snooze windows, and the two Phase-3 holes.
   The outbox is deliberately NOT a consumer — delivery-attempt semantics are
   not something a ledger primitive should learn.

2. **Every declared collection states its semantic class**, in a `@durable`
   annotation on the constant that names it: `class` (ledger / mirror /
   ephemeral / config / audit), `owner`, `write` (what causes a row) and
   `retention` (what removes one, or why nothing does). A COMMENT rather than a
   typed field, because it must also cover the collections that will never use
   a shared primitive — raw DDL, the kernel's canonical KV list, another
   package's store — and because a second typed authority is the shape this
   repo has shipped wrong twice. `docs/reference/storage.md` §3a renders it;
   `scripts/check-durable-state-declared.ts` fails a NEW collection without it,
   against a shrink-only backlog of the ones that predate the annotation.

3. **The two open holes are closed on that primitive.**
   `NodeStressMoveLedger` persists every APPLIED failover move (never an
   attempt) — the cooldown, the return ban and the 4-moves/hour budget are all
   derived from that one list, so persisting it is the whole fix. The
   device-features mirror persists its last-known features as a RESTORED cache,
   seeded at boot and reconciled by the first successful read; the device
   remains the authority and the D49 second-read rule still clears a genuinely
   empty device.

4. **A five-minute LTS tier, global for every camera.** `LtsAggregator` folds
   samples in RAM off the calls that already produce them — no new event topic,
   no new subscriber — and writes ONE row per (subject, series, scope, bucket)
   when the bucket closes. Series: `motion` (activity, valued by regionCount),
   `audio-dbfs` (the per-camera noise baseline), `battery` (discharge over
   weeks), `occupancy` (per zone and frame-wide), and the four node-stress
   signals. Retention is a **row CAP per (subject, series, scope)** — 105,120
   rows ≈ one year — deliberately not an age sweep: D61 collapsed ten
   disagreeing age clocks into one, and an LTS row summarises an interval and
   has no owner to be orphaned from.

## Consequences

- **The primitive exists TWICE**, byte for byte, in `addon-post-analysis` and
  `addon-pipeline-orchestrator`. Addons never import each other, and a
  framework home (`types`/`system`) is not live until a whole `@camstack/server`
  is published — while the holes it closes deploy today. The guard fails the
  build if the copies differ by one character, so the duplication cannot rot;
  when the framework home lands, both are deleted and imported.
- **A restart no longer grants a free failover budget.** The trade is that a
  wiped collection starts the budget cold, which is the safe direction.
- **The device-features row can be stale.** That is the point, and it is
  bounded: it is only ever consulted when the authority did not answer, it is
  overwritten by the first read that does, and serving it is logged with
  `restored: true`.
- **LTS is on for every camera with no opt-in.** An opt-in nobody enables
  produces no baseline — which is the failure mode `observe` was already in. A
  camera that produces no sample in an interval writes no row, so the rate is
  bounded by live subjects × active series × 288/day, and the aggregator is the
  only writer.
- **The mean is never stored**, only `sum`/`samples`/`min`/`max`. A stored mean
  is a derived field that can disagree with the fields it derives from and
  cannot be merged if two rows are ever combined.

## Enforcement

- `durable-ledger.spec.ts` — the contract in isolation: verdicts, the two write
  modes, `pruneExcept`/`forget`, and the D49 direction on a failed load.
- `liveness-ledger.spec.ts` (18 assertions, unchanged) — the donor's own suite
  re-run against the extracted primitive. Neutralising the seed gate fails 12
  of them.
- `node-stress-controller.spec.ts` — the cooldown and the budget each surviving
  a restart, every negative paired with a CONTROL that must still move a
  camera. Neutralising `hydrate()` fails 3.
- `device-features-mirror.spec.ts` — the cold-boot hole, plus a CONTROL that
  reproduces it when the reseed is skipped.
- `lts-aggregator.spec.ts` — the bucket boundary, write-once-when-closed, D8
  tolerance (a lost sample skews, never corrupts), and the row cap.
- `scripts/check-durable-state-declared.ts` — classification + twin identity.
