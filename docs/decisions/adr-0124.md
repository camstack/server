## Context

[D119](adr-0119.md) put every operator-visible word of Notification Center into
one catalog with a four-layer chain — rule template → hub override → shipped
locale → shipped English — and shipped the **override layer empty**, with
nothing that could write it. That was deliberate: Phase 1 only had to guarantee
that a value written there wins.

Phase 2 is the thing that writes it: a hub language setting, and a per-key
wording override an operator can edit. Two questions had to be answered before
any of it was built.

**Where does the contract live?** The obvious answer is three methods on the
`notification-rules` capability, next to `getAlarmConfig` / `setAlarmConfig`.
The cost of that answer is a release train: a `*.cap.ts` change reaches a node
only inside a published `@camstack/server` ([D16](adr-0016.md)), so the tab
would render a "not available yet" box for however long the next train takes —
for a feature whose entire value proposition is *"re-word your notifications
today"*.

**What does "saved" mean?** The durable `notification-center:texts` row is not
what a notification reads. Every producer shares ONE `NcTextCatalog` instance,
refreshed on the centre's reload tick. Persisting alone is therefore a save the
operator cannot observe until a timer fires.

## Decision

**The edit surface is three `nc.*` custom actions**, not capability methods:
`nc.getTexts` (query), `nc.setLanguage` and `nc.setTextOverrides` (mutations),
all `auth: 'admin'` — the read included, because the catalog is a system-wide
setting that spells out every sentence the hub can print. Same reasoning as the
`nc.*Timelapse*` block that preceded it: the generic `addons.custom` bridge
already carries a per-action contract, and a capability would buy a train and
nothing else. The Admin UI reaches them exactly as the Simulate and Debug tabs
reach theirs.

**Every write re-applies the live catalog** (`NcTextCatalogEditor` holds the
same `NcTextCatalog` instance the dispatcher, the timelapse producer, the snooze
digest, the alarm announcement and the history projection read). Bounded
staleness is the right answer for another node (D8); it is the wrong answer for
the node the operator is looking at.

Three shape decisions follow from the layers themselves:

- **A row carries the shipped text even when overridden.** It is the only thing
  "reset to shipped" can reset TO, and the client never sees the bundles.
- **A plural key flattens to `other` and DECLARES its categories.** An override
  is a single string, so overriding `class.person` replaces "person / people"
  with one sentence printed for every count — the surface warns before that
  happens rather than after a notification reads "1 people".
- **Blank means RESET, not "store an empty override".** `renderTemplate` treats
  a blank template as absent, so a stored blank is a row that claims to be
  customised and behaves exactly like the shipped one. A non-blank value is
  stored VERBATIM: `detection.inZones` ships as `" in {{zones}}"` and a helpful
  trim would glue it to the word before it in every notification that uses it.

## Consequences

- **Live on an `addon-post-analysis` deploy — no train.** The Admin UI tab is
  deployed separately and degrades to a named "not available on this hub" state
  until then, distinguished from both an empty catalog and a parse failure. An
  empty table would read as data loss.
- **Layer 1 stays out of reach, and the page says so.** A rule that wrote its
  own `template.title` / `template.body` still outranks everything here; the
  catalog is per-key and a rule template is per-rule. Promising otherwise would
  be a surface that appears not to work on exactly the rules an operator cares
  most about.
- **A patch, never the whole map.** Two admins editing different keys must not
  overwrite each other, and a wholesale PUT makes that outcome the default. The
  writer re-reads before merging, and refuses the WHOLE patch on any key no
  shipped locale carries — a dead override renders nothing and sits in the table
  looking like a working customisation.
- **A language may be viewed without being adopted.** `nc.getTexts` takes an
  optional language, so an operator can pre-translate `it` while the hub still
  speaks `en` — the alternative is a household reading half-translated
  notifications for as long as the typing takes.
- **One placeholder grammar.** `templatePlaceholders` and `renderTemplate` share
  a single regex in `render-template.ts`; a second one would be a legend that
  disagrees with the renderer about what a variable is.
- **The catalog contract stays addon-local.** `NcTextCatalogViewSchema` lives in
  `addon-post-analysis` and the Admin UI narrows the `z.unknown()` reply by hand
  in one file, with type guards. That is the price of skipping the train, and it
  is the same price `debug.*` and `nc.injectTestEvent` already pay.

## Enforcement

Unit tests, neutralisation-verified: removing `catalog.apply(...)` from
`setLanguage` / `setOverrides` turns three editor specs RED (a save that only
persists), and collapsing the blank-or-shipped rule in `buildOverridePatch`
turns four admin-helper specs RED (a reset silently stored as an override).
`scripts/check-nc-text-catalog.ts` (D119) continues to keep the shipped files at
parity, which is what makes the `fallback` provenance a real state rather than a
routine one.
