## Context

The hand-written structure map in `CLAUDE.md` listed **9 packages that no longer
existed** (`packages/kernel`, `packages/core`, `packages/addon-detection-pipeline`, <!-- drift-ok: these are the dead paths being described -->
…) and omitted roughly 25 that did. Eight of its 24 file references pointed at
moved files. The invariants it described were, on inspection, still accurate — the
*facts* had rotted while the *reasoning* survived.

Nothing failed, because nothing checked. And the audit turned up three cases of the
same shape elsewhere: an orphaned doc comment describing a sleeping-camera gate
whose code had been removed, vestigial test wiring for a check that no longer ran,
and a test fake that pre-seeded the value the production code forgot to fetch. In
each, the leftover described the *right* design while the live code had drifted —
which is worse than no documentation, because it reads as verification.

The pattern: **anything derivable that is maintained by hand will drift, and its
drift will be invisible.**

## Decision

Split documentation by whether it can be derived.

**Derived — generated, never edited** (`scripts/docs-generate.ts`, run by the
pre-commit hook and verified by CI):
`docs/reference/packages.md`, `addons.md`, `capabilities.md`, `guards.md`, and
`docs/decisions/index.md`. Each carries a DO-NOT-EDIT banner. Roles and shipping
channels are derived from the root package's dependency closure, not from a
hand-kept list.

**Prose — hand-written, mechanically guarded** (`scripts/check-docs-drift.ts`):
architecture pages and decision records. Every repo path a doc mentions must
resolve, including `file.ts:123` line numbers; a frontmatter `applies-to` glob
matching nothing fails.

**Staleness is reported, never failed.** If code under `applies-to` changed after
a doc's `last-verified` date, the checker prints it. Failing would force a doc edit
to land an unrelated commit — the treadmill this whole arrangement exists to
remove, and the reason the previous docs rotted rather than being deleted.

## Consequences

- `CLAUDE.md` gets shorter as more becomes derivable. It should hold rules and
  reasoning, and link to generated pages for facts.
- A new package, addon or capability documents itself on the commit that adds it.
- Prose can still be *wrong* — the guard only proves it points at real code. The
  `last-verified` report is the honest signal about the rest.
- The generated pages surfaced real drift immediately, including three
  `camstack.system` flags that disagree with the Dockerfile's own framework set,
  and seven repository guards that existed, passed, and were never wired into CI.

## Enforcement

`npm run docs:check` in CI (`docs-generate --check` + `check-docs-drift`);
`.husky/pre-commit` regenerates and re-stages `docs/reference/` whenever a
manifest or a `*.cap.ts` is part of the commit, then runs the drift guard.
