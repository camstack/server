## Context

An occupancy rule counts `byClass[className]` straight out of the ZoneAnalytics
snapshot. That record is keyed on MACRO classes only — the executor maps every
raw COCO label onto its macro and drops the rest (`COCO_TO_MACRO.preserveOriginal
=== false`). Occupancy is also the ONE class condition that does not go through
the rule engine's macro-expanding `expandClassSelector`, so nothing downstream
widens a sub-type back out.

Every rule editor nonetheless offered the whole taxonomy for it, because the
occupancy widget reused `pickerForCondition('classes', …)` — which is correct for
every OTHER class condition. On 2026-08-12 two rules on device 102
("Pat è tornato" / "Pat è andato via") were authored on `car`. They could not
fire: the key does not exist, the counter reads 0 on every frame, no predicate
ever flips. Nothing said so anywhere — the dry-run showed "0/1 car · not occupied
now", which is pixel-identical to a genuinely empty parking space. They were
repaired live to `vehicle`.

The same investigation found the second half. `seedState` had already fixed "the
already-parked car announces its own arrival" by writing the first observed level
into the watcher instead of a fabricated zero — but into RAM only. The durable
write-through fired on committed EDGES, so every restart threw the baseline away
and re-seeded from whatever the first post-boot snapshot said. A car that left
during the downtime came back as a phantom re-seed, and its departure was never
announced.

## Decision

A count keyed by class may only be scoped to a MACRO class
(`isDetectionMacroClass`, derived from `MACRO_LABELS` — never hand-listed). Every
editor offers `pickerForCondition('occupancy', …)`, which is macro-only, and the
watcher REPORTS a stored scope that is not (once per key, `tags: { deviceId }`),
because a branch that counts nothing forever is a dropped branch.

And the level a key starts from is durable: the cold seed is drained from
`OccupancyWatcher.takeSeededRows()` and written through the SAME ledger the edges
use. A seed still fires nothing, and a durable row still wins on reseed.

## Consequences

A sub-type occupancy rule can no longer be authored. Rules that already carry one
are NOT rewritten — the dead value is shown, flagged, in both editors ("sub-type,
never counts") and in the tester's label, because hiding it would blank the
control for exactly the rules that need fixing.

The macro vocabulary is now load-bearing in a second place: adding a macro to
`MACRO_LABELS` widens what an occupancy rule may count, automatically.

The durable seed adds one write per key, ever — not per frame. A failed write
degrades to exactly the old behaviour (a cold re-seed at the next boot), so it
stays best-effort and never throws into the frame path.

One hole remains, deliberately out of scope: the viewer's
`reconcileOccupancyClasses` adopts a single authored `classes` entry as the
occupancy scope, and it cannot tell a macro from a sub-type without the taxonomy
it is not passed. A rule saved as `classes: ['car']` + occupancy therefore still
lands on `car` — and is then reported by the watcher and flagged by the tester.

## Enforcement

Unit tests on both sides of the picker (`condition-taxonomy.spec.ts` in
`@camstack/types` and in the viewer's pinned copy; `NotificationRuleConditions.spec.tsx`),
`occupancy-seed-persist.spec.ts` for the drain/hydrate/restart contract, and
`notification-center.spec.ts` for the end-to-end durable write. At runtime the
`occupancy key can never count` WARN and the tester's label are the enforcement
for a rule that predates the picker. No static guard: "which condition reads a
count rather than matching" is not derivable from a manifest.
