## Context

`{dataDir}/addons/manifest.json` records what is installed: name, version,
source, timestamps, rollback pointer. `reconcileFromDisk` existed to ADD
image-seeded addons that never pass through an install codepath (without it,
`applyUpdate` rejected them as "not currently tracked in manifest" and "Update
all" was dead on a fresh image). It deliberately left existing entries alone —
"their source, version and timestamps are authoritative".

Drift therefore accumulated in one direction forever. On 2026-08-07 the live hub
listed three packages with **no directory on disk** (`@camstack/system 1.2.29`,
`addon-viewer-ui 1.1.39`, `addon-agent-ui 1.2.4`) and recorded
`addon-decoder-nodeav 1.2.4` against a 1.2.9 install. The agent was worse: six
addons recorded `1.2.0` against installs up to `1.2.21`. `@camstack/system` is
the instructive one — [D45](adr-0045.md) stopped seeding it under `addonsDir`
because a copy there shadows the closure and never updates, so the manifest was
advertising a copy that must not exist.

## Decision

**The directory is the truth**, because the directory is what `AddonLoader`
runs. `reconcileFromDisk` runs on every boot and makes three corrections:

- **added** — an on-disk addon with no entry gets one, `source: 'seed'`.
- **version-corrected** — an entry disagreeing with the installed
  `package.json` adopts the DISK version. `source` and `installedAt` are not
  derivable from disk and stay authoritative in the manifest; `updatedAt` is
  left alone, because a correction is not an update and stamping `now` would
  claim an install that never happened.
- **pruned** — an entry naming a directory that does not exist is removed,
  **unless** it holds a `lastBackupDir`. That pointer is the only reference to a
  pre-update backup, and the launcher's backup sweep reclaims whatever the
  manifest does not point at.

Every correction is logged by name. The reconcile runs after
`ensureRequiredPackages` and before any update can be in flight.

Directory detection follows symlinks (`fs.statSync`), never `Dirent.isDirectory()`.

## Consequences

- The manifest can no longer report a version the node is not running, or a
  package it does not have.
- Pruning is destructive to manifest state, so it must never run while an
  install is mid-flight — the launcher's ordering is load-bearing, not
  incidental.
- The symlink rule is load-bearing in dev: `installSymlink` points
  `addonsDir/@camstack/<pkg>` at the workspace source, and a `Dirent.isDirectory()`
  check answers false for it. With pruning added, trusting the dirent would have
  emptied a developer's manifest on the first boot. This was caught by a dry run
  against a real overlay, NOT by the unit tests written alongside the change.

## Enforcement

`packages/system/src/kernel/__tests__/addon-manifest.spec.ts` covers each
correction, the rollback-pointer exception, convergence on a second pass, and a
symlinked addon dir. Review-only for the launcher ordering.
