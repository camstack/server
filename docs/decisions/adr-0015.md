## Context

An addon that resolves its framework dependencies from the host is coupled to the
host's exact version of them. That is fine for one shipped artifact and untenable
for a fleet, because an addon and the framework update through different channels
at different times: an addon arrives via `camstack deploy`, the framework via a
root-package install. Version skew is the normal state, not an error state.

The specific breakage was worse than a missing export. Capability dispatch
compared Zod schema *identity*, so an addon carrying its own `zod` could not
satisfy a capability defined with the host's `zod` — the objects were structurally
identical and referentially different.

## Decision

Each addon bundle carries its own copy of `@camstack/types`, `@camstack/sdk`,
`zod` and `@trpc/*`. Capability dispatch is **structural**: no schema identity
check crosses a bundle boundary.

Exactly five packages stay external, resolved from the running host closure:

| External | Why it cannot be bundled |
| --- | --- |
| `@camstack/system` | owns the process, the registries and native `better-sqlite3` |
| `@camstack/ui-library` | shared React composites — two copies means two Reacts |
| `@camstack/shm-ring` | native addon |
| `@camstack/sdk` | external for addons that need the host's link chain |
| `@camstack/types/*` **subpaths** | `types/node` carries the filesystem storage provider |

Note the asymmetry on the last row: the **bare** `@camstack/types` entry is
bundled, while every subpath stays host-resolved. A bare-string external matches
only the exact specifier, which is why this has to be spelled out.

## Consequences

- An addon built against an older `@camstack/types` keeps working, as long as the
  capability's payload shape is compatible. Additive fields are safe; that is why
  an additive change needs only the providing addon redeployed.
- `camstack.system: true` in a `package.json` is a **UI** flag (surface it as
  un-uninstallable), not the shipping mechanism. The mechanism is the root
  package's dependency closure — the two disagree today for `types`, `sdk` and
  `shm-ring`, and `docs/reference/packages.md` derives roles from the closure for
  that reason.

## Enforcement

`tools/build/vite-lib.preset.ts` owns the externals lists, so the build shape is
declared in one place. `scripts/check-deps.ts` (CI) verifies every `@camstack/*`
import is a declared dependency.
