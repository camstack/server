## Context

[D52](adr-0052.md) and [D56](adr-0056.md) made the CLIP index rebuildable: one
crop derivation, one pinned model, any capable node. Both rebuild **from the
track's stored `keyFrame`** — a native full frame captured live. A track without
one cannot be re-embedded by any of that machinery, ever.

Measured on the live hub, 2026-08-06, over a 7-day window: **790 of 3,633 tracks
(21.7%) have no key frame**, 110–390 per day. The cause was not eviction and not
an unreadable blob. `keyFrame` and `keyFrameSmall` are written in the same block
and across the 2,855 tracks that have them the counts are **exactly equal**;
`media read failed — row kept but blob missing` was 0 on each of five
consecutive days; a missing track on disk holds `firstFrame`, `lastFrame`,
`thumbnail` and `thumbnailSmall` and no `keyFrame.jpg`. They were never written.

Two lines a few apart in `buildSnapshotTargets` had diverged:

```
thumbnail:  isNewBest || !thumbnailLanded    ← re-fires every frame until one lands
keyFrame:   isNewBest                        ← only
```

`isNewBest` is a best-frame PEAK signal (hysteresis 0.05, 2 s min gap), so most
tracks raise it once. Of 102 tracks that logged a native-capture miss that day,
**494 (80%) got exactly one attempt in their whole life**; 101 got 2, 20 got 3,
2 got 4. The miss line said "will retry next best" and for four tracks in five
there was no next best. Nothing at close recovers it: `pipeline/track-close.ts`
derives the thumbnail FROM the key frame, never the reverse. Of the miss-logged
tracks that survived, **388/542 (71.6%) never got one**.

A separate finding sat underneath. **403 of the day's misses were a swallowed
exception** — `pipelineRunner.getNativeCrop not routable to node <X>:
node-offline`, logged at `debug` and therefore absent from Loki entirely. 388 of
those belonged to ONE developer laptop that had acted as an agent node and gone
offline; every frame of every camera it owned kept issuing captures that could
not resolve. A third of the failures were invisible, and the fetches were free
to no one.

The standing note that a ~50% native-lease miss rate is "retry by design, do not
raise the TTL" (memory `native-lease-miss-economics`,
[post-analysis.md](../architecture/post-analysis.md)) is **true for every kind
that retries and false for `keyFrame`, the one that did not**. The TTL was never
the problem.

Rejected on the way:

- **Raising the native lease TTL.** It buys a higher first-attempt hit rate at
  the cost of retention memory on the decode worker, and leaves the one-attempt
  ceiling exactly where it was.
- **Falling back to `thumbnail`.** It is a tight subject crop; re-cutting an
  embedding window from it produces a second feature space — precisely the D52
  failure the rebuild exists to prevent.
- **Falling back to `firstFrame`.** It is a BOXED timeline tile; the drawn
  rectangle would be embedded. Both are present for most of the missing tracks
  and both are wrong.
- **An unbounded per-frame retry**, matching the thumbnail exactly. A key-frame
  attempt is a native full-frame fetch at 4096 px, the most expensive capture in
  the addon. The hub was measured the same night at 70–95% main thread, load 29
  on 20 cores, with 42 s of synchronous blocks in a 120 s window.

## Decision

**Media that a later pass depends on is retried until it lands.** The gate is
`landed`, not a peak: `(isNewBest || !keyFrameLanded) && plausibleBox`, with
`keyFrameLanded` set only on a real `putReplacing`.

Because the retry is not free, the catch-up path — and only the catch-up path —
is bounded three ways: at most **3 retries per track**, never closer than
**2 s**, and dispatched at a **lower scheduler priority (3)** than the tier-1
`keyFrame` (1) and the `thumbnail` (2), so a retry can only ever claim a device
lane slot the live media ladder did not want. A genuine new-best is uncharged:
it is already rate-limited by the best-frame policy.

**A capture is never dispatched at a node the cluster registry has already
called dead.** Liveness is mirrored from `EventCategory.ClusterTopologySnapshot`
— the hub's own `HubNodeRegistry` view, pushed on every lifecycle change plus a
30 s heartbeat — never polled and never probed. A frame handle whose owner is
known-offline is treated as ABSENT, which is a path the addon already handles
well. The mirror is deliberately reluctant, per [D49](adr-0049.md): an unknown
node is never gated, a node that DISAPPEARS from a snapshot is unknown again,
`isOnline: false` must arrive twice running, and a mirror nobody refreshed for
120 s stops gating anything. All four fall open.

**And the capture path carries a per-device hit/miss metric**, because before
this one there was none: `fetchNativeFullFrameTiered` never touched
`bumpCropMetric` (only `getNativeCropJpeg` and `captureCrop` do), and that
counter is process-global with no `deviceId` anyway.

## Consequences

- **Worst case added fetch rate: 3 extra native full-frame fetches per track,
  ever**, no two closer than 2 s, and only while the track has no key frame. Per
  camera that is at most `3 × (tracks simultaneously without one)`, itself capped
  by the scheduler's 3-in-flight-per-device budget. On the measured fleet — 388
  surviving miss-logged tracks a day — the ceiling is ~1,164 extra fetches/day
  fleet-wide, ~0.013/s.
- A camera whose owning node dies now produces **no media at all** rather than a
  storm of failing fetches. That is a real loss of the thing that was never
  arriving anyway, and it is logged on the transition with `tags: { deviceId }`
  and the node id.
- The gate is placed at the TOP of `processFrame`, so it also spares the
  confirmation gate's crop. Births on that camera confirm immediately and
  unmeasured — the documented handle-less behaviour, and better than deferring
  every birth for 2 s against a node that cannot answer.
- `keyFrameLanded` is per-track RAM state cleared at close. A track that closes
  without a key frame is not retried later; only a live track catches up. There
  is no historical backfill, and there cannot be — the pixels are gone.
- The exec body moved to `pipeline/key-frame-persist.ts` and returns a
  discriminated outcome. `persistKeyFrames` keeps only the scheduling. The
  `TrackSnapshotTarget.keyFrame` flag became a three-valued
  `'skip' | 'new-best' | 'retry'`, because a retry and a peak differ in priority
  and in budget and a boolean lost that.
- `RebuildOutcome` gains `missingEvent`, split out of `missingKeyFrame`: no
  object event (a track-store problem) and no key frame (a media problem) are
  different people's problems. The cap-facing status still reports the sum, so
  no capability schema changed; the split lives in the logs.

## Enforcement

Tests, each verified to go red when its fix is removed, with the count:

- `packages/addon-post-analysis/src/pipeline-analytics/__tests__/key-frame-retry-e2e.spec.ts`
  boots the real addon against a fake `pipelineRunner.getNativeCrop` and counts
  the full-frame requests at the native cap. Reverting the retry gate to
  `isNewBest && plausibleBox` turns **3 tests red, each reporting exactly 1
  attempt** — the measured defect, reproduced. Forcing `captureNodeOffline`
  false turns **2 red** (18 and 7 requests that should have been 0). This spec
  exists because the defect was never in a decision function, it was in whether
  the frame loop consulted one.
- `.../pipeline/__tests__/key-frame-persist.spec.ts` — all three drop branches,
  each carrying `tags: { deviceId }` and the owning node. Restoring the `debug`
  level turns **2 red** here plus **1** in the e2e.
- `.../pipeline/__tests__/key-frame-retry.spec.ts` — the bound, the min gap, the
  new-best exemption, and that the retry priority sits below tier-1 and above
  enrichment.
- `.../runtime/__tests__/node-liveness.spec.ts` — one test per direction the
  mirror must fall open.
- `.../pipeline/__tests__/key-frame-metrics.spec.ts` — the window separates the
  retry path, which is the number that says this change worked.

Not enforced by a guard: that the per-device key-frame window line is actually
emitted from `persistKeyFrames`. The aggregator is unit-tested and the call is
type-checked, but a future edit could drop the `note()` call and no test would
notice. The existing `native-fetch-guard.spec.ts` continues to hold every raw
native fetch inside a `CaptureScheduler` exec.
