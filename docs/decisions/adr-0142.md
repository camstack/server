## Context

Two separate defects, both about the same sentence — "Alice è arrivato".

**The name arrives after the notification does.** A notification's TEXT is
frozen at enqueue (`buildTemplateVars` reads `subject.label`), while its MEDIA is
re-resolved at send. An `immediate` rule enqueues on the first object event; a
face identity is written on the TRACK after `confirmFrames` agreeing
observations, measured on this hub at **p50 11.4 s from `firstSeen`**. So the
notification for a recognised person shipped, systematically, without the
person's name in it, and no amount of media re-resolution fixes a sentence.
Plates were the mirror-image trap: `plate-detection` runs `once`, so a plate is
frequently read on the first frame (0.0 s observed) and the identity IS
available at enqueue.

**The name was also the key.** `identities` matched the record's collapsed
display label. A display name is renameable, so fixing a spelling in the face
gallery silently un-matched every rule that named that person. The rule still
existed, still read correctly in the editor, and covered nobody. Nothing said
so. The gallery has had a stable `Identity.id` (uuid) since it was written; it
simply never reached the record — `LabelCandidate` and `LabelAttribution`
carried `stepId`/`modelId`/`decidedAt` and no id.

A third defect fell out of the same read: `hasTrackLabel` — the gate that drops
ArcFace on a periodic face refresh — read the tier-1 `label` column, while an
identity lands in tier-2 `subLabel`. It was wrong in both directions at once: a
track ArcFace had already named kept re-embedding forever, and a track carrying
only a sub-class (`van`) had its face chain suppressed.

## Decision

**The gallery id travels with the label.** `LabelAttribution.identityId` carries
the face `Identity.id` or the plate `Vehicle.id` behind a tier-2 value, written
by every producer of one (the recogniser, both operator overrides, the live
plate path). `NcConditions.identities` / `identitiesExclude` are matched on it.
Display names in stored rules are resolved to ids **lazily, on read**
(`NcRuleStore.load`), as a projection that never writes back: a name the gallery
cannot answer for is KEPT and reported, and an empty/failed gallery read
migrates nothing. The engine keeps a display-name leg so neither an unmigrated
rule nor a pre-id record goes dark.

**An identity or plate condition has three states**, and the empty list is the
middle one: absent = "any subject", `[]` = "only known faces / any readable
plate", a list = those. This is the repo-wide "no selection = no narrowing"
reading applied one level down, and it is why no second on/off field exists — a
switch that can disagree with the list under it is worse than no switch (D62).
"Any known face" is decided from the label's PROVENANCE (`labelKindOf`), never
from the word.

**`NcRule.waitForEnhancement` picks between the only two honest timings**, and
has effect only on an `immediate` rule that declares a recognition scope:

- **ON** — the rule is removed from the object-event trigger and evaluated
  against the CLOSED TRACK instead. One notification, with the name.
- **OFF** — it fires at once without the name; if the track closes carrying a
  name the first push did not have, ONE follow-up row is enqueued under the
  dedup ref `<trackId>:enhanced`, addressed only to the targets the first push
  actually reached.

**`detection.subject.identity` and `detection.subject.plate`** are separate
catalog keys. A person takes a verb and a plate takes a noun, and Italian will
not agree the gender across them; one `{{label}}` slot cannot word both.

## Consequences

- **Train-bound.** `waitForEnhancement`, the widened `NcPlateMatcher.values` and
  `LabelAttribution.identityId` are `@camstack/types`; a rule cannot be authored
  with the flag until a `@camstack/server` closure carrying it is installed —
  the generated router validates `createRule` against the HOST schema and
  strips/rejects otherwise.
- **`waitForEnhancement: true` buys track-close SEMANTICS with the name.** The
  rule's `zones` condition then tests every zone the track visited, and a
  `crossing` condition can no longer be satisfied. Stated in the schema and
  repeated in the editor.
- **The deferral MUST remove the rule from the object-event trigger.** Leaving
  it on both would fire the early, nameless notification, and the
  `ruleId:trackId:targetId` dedup key would then discard the complete one as its
  duplicate — the operator would receive exactly what they set the flag to
  avoid.
- **The upgrade's "did the first one fire" memory is in RAM**
  (`recognitionFires`, 30-minute TTL). Losing it on a respawn costs an upgrade,
  which degrades to the state of the world before this feature. It is not made
  durable because that trades an unnoticeable loss for a second write on the
  enqueue path.
- **The events are now a denormalised COPY of the track's label**
  (`EventStore.projectTrackLabel`), not a second evaluation of the candidate,
  and the frame emitter stamps the track's known answer on rows emitted after
  the recogniser answered. Both halves are needed: the back-patch was filling
  rows behind an emitter that kept digging, and per-row re-decision let a row
  whose incumbent outscored the winner keep a different word — 407 of 437 tracks
  disagreed with their own events.
- A track that is neither active nor persisted can no longer be labelled through
  its events, because there is no track decision to copy. This is visible only
  in tests that omitted the track row.

## Enforcement

- `recognition-timing.spec.ts` pins both timings on the REAL centre and outbox,
  with neutralisations for each: the flag off fires immediately, the flag on a
  scope-less rule is inert, an unchanged word sends nothing, a rule that never
  fired is owed nothing, and a replayed close adds nothing.
- `rule-engine-identity.spec.ts` pins id matching (with a wrong-id
  neutralisation, so the pass cannot be coming from the name), the name
  compatibility leg, and all three list states for faces and plates.
- `rule-store-identity-migration.spec.ts` pins idempotence, the KEPT
  unresolvable name, and — the neutralisation that matters — that an EMPTY
  gallery rewrites nothing.
- `label-recognition.spec.ts` pins `hasResolvedLabel` on tier 2, `labelKindOf`
  for both families and their operator overrides, and that a silent track yields
  no patch.
- `event-store.spec.ts` pins that a row whose own incumbent outscores the track
  decision is overwritten anyway.
- `check-viewer-condition-mirror.ts` and `check-nc-text-catalog.ts` cover the
  descriptor enums and the two new locale keys. Nothing guards that a NEW
  tier-2-producing step adds itself to `FACE_LABEL_STEP_IDS` /
  `PLATE_LABEL_STEP_IDS`; it degrades to the generic labelled sentence, which is
  what every notification said before these keys existed.
