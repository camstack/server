## Context

Notification Center had **six text-birth sites**, each of which had decided the
same questions independently:

- `dispatcher.ts` built the default detection body by string concatenation
  (`${className}${label} on ${deviceName}${zones}${suffix}`) and owned a private
  `occupancyOpWord`;
- `event-intake.ts` froze finished English SENTENCES onto the durable outbox row
  at intake (`Camera 101 is offline`);
- `timelapse-delivery.ts` built its body in **hard-coded Italian**
  (`intervalli ripresi a cadenza fitta` [intervals shot at a dense cadence], `ATTENZIONE: registrazione disponibile
  solo per il N% della finestra` [WARNING: recording available only for N% of the window]), with a six-word Italian noun table in
  `detection-counts.ts` beside it;
- `snooze-digest.ts` and `alarm/alarm-mode-coverage.ts` each carried a private
  `plural(n)` helper — an `n === 1` check with the English suffix baked in.

Two of those are not merely untidy, they are unfixable in place:

1. **A frozen sentence cannot be re-worded.** An outbox row is durable and may
   sit for days behind an unreachable target. The words a system-event row was
   born with were the words it would forever be delivered with, so correcting a
   sentence could never reach a queued row and translating one could never reach
   any row at all.
2. **`n === 1` is not a plural rule.** It is right for English and wrong for most
   other languages. Its actual cost was already shipped and visible: the
   timelapse body said *"1 intervalli ripresi a cadenza fitta"*.

The obvious first move — sprinkle a translation function over the concatenations
— does not work here. `renderTemplate` is a single-pass `{{var}}` substitution
where a missing name renders empty, and a body like `person (John) on Front door
in gate` is not a sentence with slots: the label parentheses, the zone clause and
the plural noun each have a language-dependent SHAPE and a conditional presence.
Expressing that as `{{class}}{{label}}{{zones}}` pushes the grammar into the
template, where a translator cannot reach it.

## Decision

Every operator-visible word in Notification Center comes from **one catalog**,
addressed by a flat key, resolved in this order: the rule's own template → the
hub override for the active language → the shipped file for that language → the
shipped English file. Plural variants are selected by `Intl.PluralRules` **for
the resolved language**, and lists are joined by `Intl.ListFormat`.

Sub-phrases whose grammar is language-dependent become **composite variables** —
`{{subject}}`, `{{inZones}}`, `{{op}}`, `{{detectionSummary}}` — rendered FIRST
from their own fragment keys against the SCALAR variables only, then injected
into the single final pass as plain strings.

A producer writing a DURABLE row freezes the **key and its params**, never the
sentence, and picks the body VARIANT (profiled or not, agent or worker,
node-pinned or not) where the fact is known — so the catalog stays a flat list of
finished sentences rather than a template language with conditionals in it.

## Consequences

- **The composition depth is exactly one, structurally.** `renderTemplate` never
  re-scans a replacement, and fragments are never handed the composite map. A
  fragment that names another composite renders it empty rather than starting a
  second round; a value that happens to look like `{{camera}}` is printed, not
  substituted. This is not a convention — there is no code path that could
  produce a second pass.
- **A pre-catalog row must still be readable.** `NcSystemEventSubject.title` /
  `.body` survive as an additive READ (the `artifacts`/`artifact` precedent):
  a key that resolves wins, so a re-worded catalog reaches an old row too, and a
  key nothing carries falls back to the sentence the row was born with. Delete
  these only once no pre-D119 row can still be in the outbox.
- **The delivery history resolves through the same catalog.** The cap contract
  wants a title and a body; a page that showed different words from the phone
  would be a second vocabulary to keep in step.
- **The timelapse still renders at ENQUEUE, so its LANGUAGE is frozen there.**
  The frozen row reading exactly as it will be delivered is worth more than
  late-binding the language of one notification a night. Stated so it is a
  decision rather than a discovery.
- Two texts changed on purpose and only two: the dense-range clause is now
  plural-correct at one, and a class list is joined by the language's own
  conjunction (`e` / `and`) instead of a comma. Every other Italian sentence is
  asserted byte-for-byte identical to what was shipped.
- `renderTemplate` moved to `render-template.ts` VERBATIM (re-exported from
  `dispatcher.ts`) so the catalog can render without an import cycle.
- **`overrides` ships empty.** Phase 2 owns the edit surface. This phase only
  guarantees that a value written there wins over the file — the property Phase 2
  must be able to build against.

## Enforcement

`scripts/check-nc-text-catalog.ts`, wired into the CI guard loop. Every failure
mode of a catalog is silent at runtime, which is correct behaviour and terrible
feedback, so the guard checks what the runtime will not complain about:

- **key parity** across the shipped locales, both directions;
- **placeholder-set equality** per key across locales AND across the plural
  variants of one value (a translation that drops `{{deviceId}}` delivers a
  sentence with a hole in it);
- **plural categories** validated against `Intl.PluralRules(<that language>)`
  itself — not a hard-coded list — with `other` mandatory, since it is the
  fallback for a count-less lookup;
- **non-emptiness**.

Neutralisation-verified: each of those five checks was made to fire by breaking
the files one way at a time. The fallback chain, the depth bound and the
legacy-row read are covered by unit tests that were each confirmed to FAIL when
the behaviour is removed.
