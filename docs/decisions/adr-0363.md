## Context

A share link (`csv_*`) is a bearer credential for one view of a few devices.
Over tRPC it is confined by a fail-closed method list per scope kind
(`share-view-access.ts`). The addon data planes are reached outside tRPC,
through the hub's `/addon/:addonId/*` gate, which resolved session JWTs and
`cst_*` scoped tokens only — so the events embed under a share link listed
its events and got 401 on every thumbnail, for devices inside its own scope
(`EVENTS-EMBED.md` §7, "tracked separately"). The Home Assistant events card
built on 2026-09-05 mints exactly such a token and showed no pictures.

Lowering the plane's `access` was already tried and changed nothing: the
gate never resolved the token at all. And resolving it for EVERY
authenticated plane would be worse — a plane that never reads the scope
would serve every device to a link scoped to two.

## Decision

`AddonDataPlaneServeOptions.share` names the share scope kinds a plane
serves; absent means a `csv_*` token is refused there (403), whatever
`access` says. The hub validates the token, refuses it unless the matched
endpoint opted into its kind, strips any `x-camstack-share-kind` /
`x-camstack-share-devices` header the client sent, and sets both from the
validated scope. A plane that opts in MUST check the blob's owning device
against `x-camstack-share-devices` and refuse an owner it cannot name — the
same fail-closed rule as the tRPC gate. The scope kinds are one list in
`@camstack/types` (`SHARE_VIEW_KINDS`); the hub's token schema and the
endpoint parser both derive from it, and an unknown kind in a plane's
declaration fails the registration loudly.

## Consequences

The event-media plane serves an `events-view` share link its own devices'
thumbnails and nothing else. Every other plane is unchanged: no opt-in, no
share traffic. A plane that opts in takes on the device check; forgetting it
is the one hole this design leaves open, so the opt-in and the check live
in the same file with the handler. The headers are trusted only because the
hub rewrites them — an addon reached without the hub in front (never, by
construction: the plane secret is the hub's) would have to trust the client.

## Enforcement

`addon-route-share-gate.spec.ts` (admit on opt-in, 403 without, 401 on an
invalid token, client headers stripped), `data-plane-endpoints-parse.spec.ts`
(unknown kind refused), `event-media-handler.spec.ts` (inside scope 200,
outside 403, unknown owner 403, no header unchanged). Review only for a new
opt-in.
