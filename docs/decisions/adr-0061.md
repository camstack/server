## Context

Retention was **ten** independent age sweeps. [D59](adr-0059.md) named four; the
other six turned up while implementing this.

| # | Sweep | Selected by | Verdict |
| --- | --- | --- | --- |
| 1 | `TrackStore.listIdsBefore` → cascade | `tracks.lastSeen`, per device | **the root** |
| 2 | `EventStore.evictBefore` — motion leg | `timestamp`, per device | terminal root |
| 3 | `EventStore.evictBefore` — audio leg | `timestamp`, per device | terminal root |
| 4 | `EventStore.evictBefore` — **object leg** | `timestamp`, per device | track-OWNED |
| 5 | `MediaStore.evictBefore` | `timestamp`, **ownerKind-blind**, fleet-min − 1 d | track-OWNED |
| 6 | `ObjectEmbeddingStore.pruneDeviceBefore` | `timestamp`, per device | track-OWNED |
| 7 | `ObjectEmbeddingStore.pruneAll` | `timestamp`, fleet-min | track-OWNED, unused |
| 8 | `FaceStore.pruneAll` — age leg | `timestamp`, global | track-OWNED |
| 9 | `PlateStore.pruneAll` — age leg | `timestamp`, global | track-OWNED |
| 10 | `SensorEventStore.evictBefore` | `timestamp`, **fleet-min** | terminal root |

Plus `FaceStore.prune`, an eleventh with no production caller at all — a
leftover describing the wrong design.

They disagreed, and two of the disagreements were **measured on the live fleet,
not theorised**:

- **CLIP vectors 14–21 days out of step with their own events** on device 104:
  events back 1.0 day, embeddings back 22.1, 1,446 of 2,222 rows pointing at
  nothing that could be rendered. Cause: events were evicted per device while
  embeddings used the fleet MINIMUM.
- **5,598 `keyFrame` media rows whose track row had already been pruned.**
  Cause: `MediaStore.evictBefore` ran on a deliberately loose fleet-minimum
  bound, so media outlived tracks by construction (media span 31.0 days against
  tracks at 7.0).

The bug class is not "a cutoff was wrong". It is that **an entity which belongs
to a track was given a clock of its own**, and two clocks that must agree
eventually will not. Making the ten cutoffs agree today would have left the
class intact.

A side finding from D59 confirmed here: the `ownerKind`-blind media sweep
deleted `identity`-owned media by age, silently defeating the enrolled-gallery
exemption that the cascade was careful to honour.

## Decision

**An entity a track owns has no clock. It is deleted when its track is deleted,
and at no other time.**

Concretely, three categories, declared once in
`retention/retention-model.ts` so the sweep, the orphan audit, the
cascade-completeness test and the CI guard all read the same list:

1. **`TRACK_OWNED_FAMILIES`** — eight families reachable from a track: object
   events, event-owned child crops, track media, face rows, face crops, plate
   rows, plate crops, the CLIP vector. Deleted **only** by the cascade.
2. **`RETENTION_ROOTS`** — the five entities an age-keyed sweep may select:
   `track` (the only one that cascades), plus `motion-event`, `audio-event`,
   `sensor-event` and `ops-log`. The membership test is not "is it small" but
   ***can its clock disagree with another entity's clock?*** If it can, it is
   owned. Motion/audio/sensor carry no `trackId`, own no media and are
   referenced by nothing; the ops log records what retention did and must
   outlive the devices it describes.
3. **`RETENTION_EXEMPT_FAMILIES`** — six families that outlive their track:
   `identity` media, `vehicle` media, assigned faces, assigned plates,
   `identity-samples`, `vehicle-samples`. Enrolment is a deliberate operator
   act; a background process does not get to undo it. `identity`/`vehicle` are
   also a central `RETENTION_EXEMPT_OWNER_KINDS` set, because the owner kind IS
   the enrolment flag — a crop is REOWNED at assignment.

**Per-device retention survives.** One sweep does not mean one cutoff: the track
sweep resolves `deviceRetentionCutoffs` per camera exactly as before (measured 1
day on 104, 7 on 101/102), and the trackless roots do too. The `minObjectCutoffMs`
fleet minimum is gone entirely — it existed only to protect entities that now
have no clock at all.

**Orphan collection is ownership-keyed and structurally distinguishable.**
Cascade-only leaks anything deleted before the cascade knew about it, so
`retention/orphan-audit.ts` asks one question per row — *does the entity that
owns you still exist?* A reader tells it apart from the age sweep by four
things, all of them structural rather than conventional:

| | Age sweep | Orphan audit |
| --- | --- | --- |
| Entry point | `sweepTrackRetention` | `runOrphanAudit` |
| Signature | takes `cutoffMs` | takes an ownership probe; **no cutoff parameter exists** |
| Log line | `analytics track retention sweep` | `analytics orphan audit` |
| Ops-log op | `'prune'` / `reason: 'retention'` | `'orphan-audit'` / `reason: 'maintenance'` |
| Interval | 5 minutes | hours (`orphanAuditIntervalHours`, default 6) |
| Default effect | deletes | **deletes nothing** (`mode: 'report'`) |

The guard enforces the boundary from the other side: `orphan-audit.ts` may not
grow a `whereBetween` on a time column, because the moment it selects by age it
has become a fifth sweep wearing a different name.

**The audit reports before it reclaims.** Default mode is `'report'`: it counts,
logs one line per collection per run — including zero, because a sweep that
silently finds nothing is indistinguishable from one that never ran — and
touches nothing. This is not caution theatre: the engine's correctness rests
entirely on an ownership model being rewritten in the same change, and a wrong
ownership model here is a delete loop pointed at the operator's database. This
repo destroyed a live 8,686-row index in one call this year.

**Ownership is DERIVED from the declared schema, not hand-listed.** A
hand-written list is what produced the orphans — someone added an owned entity
and the list was never updated. So `collection-classification.ts` reads the
ownership fact off the column declarations the tables are created from: a
collection declaring a **`trackId`** column is track-owned, and one that also
declares **`assigned`** treats an assigned row as enrolled and exempt. Two
things could not be derived, and are marked `explicit` with the reason:

- `pipeline-analytics:media` carries `(ownerKind, ownerId)` — an indirection no
  column list can express.
- `pipeline-analytics:stationary-objects` declares `sourceTrackId`. A naive "any
  column ending in TrackId" rule would classify it as owned and delete the
  parked-object registry every time a source track aged out. It is a REFERENCE:
  a parked object outliving the track that first saw it is the entire purpose of
  the registry. The derivation matches the exact name `trackId`, and this
  collection is classified by hand with that reason attached.

**The drain tolerates a row it will not delete.** `retention/track-drain.ts`
advances its offset by exactly the number of rows a page did NOT remove, instead
of the old "a non-empty page deleted nothing → stop", which let one undeletable
track halt retention for a whole device.

## Consequences

- **What a pin now costs.** D59 concluded a pin could not be built because
  pinning was four exemptions across four sweeps in a filter language
  (`where` / `whereIn` / `whereBetween`) with no negation, and because the drain
  loop halted on a row it could not delete. Both objections are gone. A pin is
  now **one exemption on one query, `TrackStore.listIdsBefore`** — everything the
  track owns is kept automatically, because nothing else deletes by age, and the
  drain steps over the pinned row. Mechanically it is the sentinel column D59
  described (`retentionAt` mirroring `lastSeen`, rewritten to a far-future value
  when pinned, so the existing `whereBetween` excludes it) applied to ONE table
  instead of four. **It is deliberately not implemented.** The flags exist
  (`markForTrain`, `debug`, D59); the policy is the operator's. What has not
  changed is the storage argument: a pin is unbounded in time by construction,
  ~2–4 MB per pinned track, so any pin design needs its own cap decided at the
  same time.
- **What the audit reporting a non-zero count means.** During cleanup of the
  historic 5,598 it means the past. **After that, it is a BUG DETECTOR, not a
  cleaner** — a non-zero count for a track-owned family says the cascade has a
  hole, and the right response is to find the hole, not to raise the reclaim
  ceiling.
- **One remaining path can delete a track-owned entity without its track**:
  `EventStore.pruneObjectEventsBefore`, reached from the operator's "delete
  events older than X" button. It is named so it cannot be mistaken for
  retention, is on no timer, is logged, and is listed in the guard as
  operator-only. Its consequences show up in the audit.
- **Behaviour changes an operator may notice.** Object events now live as long
  as their track (7 days by default) rather than `retentionObjectDays` (30) —
  in practice the cascade already got there first, which is why 19.8 days of
  object events existed against 7.0 days of tracks. Face and plate buffer rows
  now live as long as their track rather than `bufferRetentionDays` (3), bounded
  by the unchanged `bufferMaxPerDevice` (50) capacity cap.
- **Bounding over-deletion.** A cascade that over-deletes is worse than the ten
  sweeps, so: the cascade itself is unchanged in what it touches (only its
  registry construction moved); the orphan audit refuses exempt owner kinds
  before any probe runs, protects everything inside a 1-hour grace window,
  abandons a scope when a liveness probe throws rather than reading failure as
  "dead", leaves unresolvable rows alone, counts ACTIVE in-RAM tracks as
  existing (a running track has media on disk with no row behind it), and caps
  reclaims per scope per run. And it does none of that by default.
- **Not verified on live data.** There is no hub in this branch. The 5,598
  orphans, the 14–21 day skew and the per-device windows are all from earlier
  measurements, not re-measured here. The first live action should be a
  **report-mode** run, read per collection, before `orphanAuditMode` is ever set
  to `reclaim`.

## Enforcement

`scripts/check-age-keyed-retention.ts`, wired into `.github/workflows/ci.yml`.
Four checks, each a name or a declaration rather than a judgement:

1. A method under `pipeline-analytics/store/` that takes a `cutoffMs`-shaped
   parameter **and** deletes must be one of six declared roots.
2. The four removed sweeps (`MediaStore.evictBefore`,
   `ObjectEmbeddingStore.pruneAll`/`pruneDeviceBefore`, `FaceStore.prune`) may
   not come back.
3. Every `*_COLLECTION` constant must be classified in `ANALYTICS_COLLECTIONS`.
4. `orphan-audit.ts` may not gain an age RANGE filter.

**False-positive argument.** Check 1 requires BOTH a cutoff-shaped parameter and
a delete call in the same method body — so reads that filter by age (every query
in the codebase) and deletes that are not age-keyed (`deleteByTracks`,
`deleteForOwner`, `deleteByKey`) are excluded structurally, not heuristically. It
is scoped to one directory, skips tests, and the allow-list carries a `why` per
entry so widening it is a sentence someone must write.

**Blind spot, stated plainly.** A hand-rolled age delete that never names itself
— `tidy(n: number)` running `deleteWhere({ whereBetween: { timestamp: [0, n] } })`
— defeats every check here, and nothing conservative can catch it: the only
signal would be "a number compared to a timestamp column", which fires on every
legitimate query and would get the guard deleted within a week. Same for raw SQL
and for a cutoff computed in the caller. It also cannot see another addon
deleting analytics rows through the settings-store cap, and it checks structure,
not behaviour — it cannot tell you the cascade reaches every owned family.

That last gap is covered by the other half:
`retention/__tests__/cascade-completeness.spec.ts` seeds one row of **every**
family in `TRACK_OWNED_FAMILIES` plus every family in
`RETENTION_EXEMPT_FAMILIES`, prunes the track through the **shipped** registry
builder, and asserts nothing owned survives and everything exempt does. The
seeder table is typed by `TrackOwnedFamilyId`, so adding a family to the
declaration without wiring the cascade is a compile error and a test failure.
The guard stops a second CLOCK; the test stops a missing EDGE.
