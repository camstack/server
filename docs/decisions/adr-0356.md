## Context

Linked devices had two modes. `auto` linked every device sharing the
camera's location, with a container standing in for ONE primary child. On the
live fleet that was wrong in both directions at once: "Pulsante faretti
hall" holds two equal switches, and auto could only ever reach "Faretti
hall 1" — "Faretti hall 2" was unreachable by construction; while camera
104 had fifteen links, ten of them container children listed one by one. The
2026-08-26 cascade, the container-primary rule, a location-invisible-container
warning and a boot backfill all existed to make the automatic rule bearable.

The alternative considered was an auto that expands a container to every
"peer" of its primary child (same type and role). It fixes the two spotlights
and keeps growing the machinery: every new device shape needs a new rule for
what auto should mean. The operator's call: the general construction gets
messier with each rule, and a picker with suggestions is simpler than any
rule.

## Decision

A camera links its device-tree children and the list the operator picked —
nothing else. The picker (`device-multiselect` with `suggestLocation`) offers
every non-container device, SUGGESTS the ones sharing the camera's location
first, names a container child after its container, and narrows by location
and type facets before the text search. `auto` is gone: the mode key is no
longer read, the cap answers `manual`, and the location-invisible warning is
deleted with the rule it served.

A rule an operator relied on cannot vanish on an update: a one-shot boot
backfill writes what `auto` resolved into each camera's manual list once
(`legacyAutoLinkIds`, kept only for this), so the operator prunes from the
picker instead of discovering an absence. A camera already on `manual` is
untouched.

## Consequences

- Linking a new device is a deliberate act in the picker. The location
  cascade still matters — it is what makes a container child SUGGESTED.
- `legacyAutoLinkIds` is dead code the day the backfill marker is set
  everywhere; delete it with the backfill once no pre-D356 hub exists.
- The `mode` field survives on the wire (`'manual'` only) because a shipped
  viewer parses it; drop it when no client reads it.

## Enforcement

`device-linked-devices.spec.ts` (default resolves children only, the
contribution is the picker), `linked-devices-manual-backfill.spec.ts`,
`device-multiselect-linked.test.tsx` (suggested first, container never
offered, facets narrow). Review only for new callers of `legacyAutoLinkIds`.
