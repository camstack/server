## Context

`RecordingTriggers.sensorDeviceIds` shipped with a schema, a recorder that
listened on it, a retention cascade and a design note — and no control
anywhere. The operator looked at an events band, saw Motion and Audio, and
asked where the sensors were. `objectClasses` on the same schema had the
same shape. They were the fourth and fifth fields of that class found in
one week: "built but unreachable". Nothing fails on such a field. It
type-checks, its consumer is correct and tested, the docs describe it —
it is simply never written, and the description of the feature reads as
its verification.

## Decision

A `z.object` schema preceded by `// @authored-by-ui` in
`packages/types/src/interfaces/**` declares that every top-level key is
set by an operator through a UI. `scripts/check-authored-fields-reachable.ts`
refuses a key no `.tsx` under the UI roots (ui-library, admin-ui, addon
widgets, the viewer and its embed) mentions. The marker is opt-in: a
schema that is written by code, not people, does not carry it. The guard
runs in CI with the other repository guards.

## Consequences

Adding an authored field now means adding its control in the same change,
or the build says which schema is lying. The check is textual (a key
mentioned anywhere in UI source passes), so it catches absence, not a
control wired to the wrong thing — that stays on review and the field's
own test. Schemas written by machines must not carry the marker.

## Enforcement

The guard itself, wired in `.github/workflows/ci.yml`; `RecordingTriggersSchema`
is the first marked schema, and removing the sensor picker or the object
class chips from the band editor fails it (verified on `objectClasses`
before the chips existed).
