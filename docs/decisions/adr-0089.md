## Context

A track had ONE label column and four writers: the frame path stamped it at
birth, `applyTrackEnrichmentLabel` wrote the classifier / plate answer onto the
track and back-patched every already-emitted event, the FaceRecognizer wrote a
recognized identity, and the two gallery providers wrote an operator's manual
assignment. Every one of them was a bare `label = text`, so the LAST writer won
and there was no rule about who that should be.

Two live tracks exposed the two halves of the defect on the same day.
`7d1dc71e` (636) held `label = 'Turdus migratorius'` with no way to ALSO say
`bird` — the species and the sub-class both wanted the one slot. `9c05543f`
(592) was a `person` track whose label REGRESSED to the macro class `animal`,
and four more like it turned up across 104/103/637 inside a week.

The macro-class rule shipped first (2026-08-07) and is correct, but it treats
only the regression, not the collision. Its own silence was the second lesson:
the five rows were found by reading the rows a week later, because the branch
dropped the candidate without a word (fixed 2026-08-08, `label tier collapse
refused`).

The obvious shape — an array of labels with tiers — was considered and
rejected: every consumer wants "the coarse one" or "the fine one", and an array
made both a scan on a row that is read at list-render rates.

## Decision

A track / ObjectEvent / KeyEvent carries **two scalar label slots**: `label` is
tier 1 (the SUB-CLASS — `dog`, `bird`, `van`) and `subLabel` is tier 2 (the
INSTANCE — `Turdus migratorius`, `Alice`, a plate read). Each carries its own
score and a `LabelAttribution` (`stepId` / `modelId` / `decidedAt`). The macro
class is not a tier: it is `className`, and a macro token offered for either
slot is refused.

**Which slot a step's answer occupies is DECLARED on
`StepDefinition.labelTier`, never inferred.** The declaration travels on the
wire (`ScoredLabel.tier`, `DetailResult.labelTier`,
`DetectionDebug.originalClassTier`), and a label that arrives without one is
REFUSED and logged. Nothing downstream may derive a tier from the step's name,
its `outputClasses`, or the shape of the text — the shape of a string cannot
tell `Bird` the surname from `bird` the sub-class.

**One rule performs every write**: `resolveTieredLabelWrite`. A higher tier is
never overwritten by a lower one — structurally, because they are different
columns. Within a tier, a strictly higher score wins.

**What a human is shown is `subLabel ?? label`** (`displayLabel`), asked at
every read surface. No consumer reads a tier column to render a name.

## Consequences

- **Two exceptions to the score comparison, both explicit.** An
  `operatorAuthority` candidate (a face named in the gallery, a plate bound to a
  vehicle) takes its tier without comparison — arcface routinely answers at 1.0,
  and without this a hand correction would silently do nothing. And an incumbent
  attributed to `migration:4g` loses to ANY properly-attributed write of its
  tier, which is what makes the migration's guess safe rather than permanent.
- **Deploy order is load-bearing.** `addon-pipeline` carries the declarations;
  `addon-post-analysis` refuses an undeclared label. Deploying post-analysis
  first drops enrichment labels until pipeline follows. And the six new columns
  reach SQLite only when `declareCollection` re-runs `ensureTable` with a
  CHANGED fingerprint (the 2026-08-08 fix), so the framework goes first of all.
- **Pre-4g rows are migrated DOWN, never up.** Nothing recorded which step
  decided a pre-tier label, so the migration puts every non-macro value in tier
  2: moving a real `dog` down costs nothing (display reads the fallback, tier 1
  stays free), while moving a species up would park it in the coarse slot and
  block the `bird` that belongs there — recreating this defect permanently.
- **`alternateLabels` is still NOT persisted**, and this record does not change
  that. The assembler computes the per-step top-N only under
  `verbosity: 'full'`, gated with `mask` and `stepLatencyMs` because it is
  expensive per frame. Persisting it needs a new emission path and per-track
  storage for a field no consumer reads today. See
  `docs/architecture/post-analysis.md` for what would have to change first.
- A cap-schema change means codegen, and the new fields are invisible until a
  `@camstack/server` carrying this `@camstack/types` is installed: the backend's
  Zod output parse strips what its own schema does not know.

## Enforcement

- `packages/addon-pipeline/src/__tests__/guards/label-tier-declared.guard.ts` (CI): every step whose `outputClasses`
  contains a label-bearing class — not a macro class, not an opaque artifact —
  declares `labelTier`. Macro classes and artifacts are ENUMERATED and anything
  else is assumed to be a label, so a new artifact class must be added
  deliberately by the person who knows the answer.
- `pipeline/__tests__/label-tier.spec.ts`: the undeclared-tier refusal is not
  rescued by the step id or by the shape of the text; a tier-1 write at a HIGHER
  score leaves tier 2 untouched; an equal score keeps the incumbent.
- `store/__tests__/label-tier-migration.spec.ts`: a migrated value is still
  correctable by a score-0 declared write, while the same value with a real
  attribution is not.
