# Building UI in CamStack

The rules for building a surface in either client. The architecture — how the
admin UI is mounted, how data reaches it, where a settings schema lands — is
[`docs/architecture/ui.md`](../architecture/ui.md); these pages say which
component, which token and which pattern.

**Workflow first.** An agent (Claude Code, Cursor, Codex) loads the
`camstack-ui` skill (`.claude/skills/camstack-ui/SKILL.md`) and then
`camstack-ui-admin` or `camstack-ui-viewer`. The skills are the procedure;
these pages are what the procedure reads.

## The local tools

None needs the MCP, a build or the network. All read the committed catalogue
`docs/reference/ui-components.json` (generated by
`scripts/ui/gen-ui-catalogue.ts`; the pre-commit hook regenerates it).

| Command | Does |
| --- | --- |
| `npm run ui:find -- "<need>"` | ranks need-table rows and library exports for a need |
| `npm run ui:show -- <Name>` | one export: file, summary, props, and real call sites |
| `npm run ui:tokens -- [admin\|viewer]` | the colour tokens, web ↔ viewer, with drift marked |
| `npm run ui:i18n` | the i18n guard: no admin-ui / ui-library literal bypasses `t()` — see below |
| `npm run ui:check -- <files…>` | raw hex / `rgb()`, palette classes, inline styles, raw `<button>` / `<table>` / `<select>` / hand-rolled dialogs — each with its replacement |

### Words go through i18n

Every user-visible word in `addon-admin-ui` and `ui-library` has a key in both
`packages/addon-admin-ui/src/i18n/en.json` and `it.json`.

- admin-ui: `t('section.key')`; a sentence with inline elements is ONE
  `<Trans i18nKey components={{ b: <strong /> }} />` key, never concatenated
  fragments; plurals are `key_one` / `key_other` with `count`, never a ternary
  suffix; a module-level table stores a `labelKey`, resolved with `t` at render.
- ui-library carries no catalogue: a composite calls `useUiText()` for
  `t('uiLibrary.<component>.<name>', 'English', vars)` (or `<UiTrans>`); the
  admin hands it the real translator through `AdminUiTextProvider`, and without
  a provider the English fallback renders.
- `npm run ui:i18n` (`scripts/check-admin-i18n.ts`, in the on-demand Checks
  workflow) fails on any remaining literal; the key-parity spec fails on a key
  missing from either catalogue. Intentional non-text (a brand name, a literal
  field name, a code sample, an example value) is exempted in place with
  `i18n-ignore: <reason>` (same or next line) or an
  `i18n-ignore-start` ... `i18n-ignore-end` block; see the header of
  `scripts/i18n/find-untranslated-admin.ts`. A bare lowercase word counts as
  prose.
- New keys: `python3 scripts/i18n/add-admin-keys.py fragment.json` merges
  `{ "a.b": ["English", "Italiano"] }` into both catalogues.

`ui:check` is a developer tool. The pre-commit hook runs it on staged UI files
and only prints; it is never a CI gate (operator decision, 2026-10-09). The
viewer repository has its own `npm run ui:check` with React Native rules.
